# Ostrovok AI Agent

> Каркас проекта команды «О!Хакатон 2026» (Компания «Островок» / Ostrovok.tech).  
> Трек №2: «О!дин запрос» (AI-агент для умного поиска и бронирования отелей).  
> Слоган: «Скажи, куда хочешь отправиться. Остальное устроит агент».

---

## 1. Быстрый старт для жюри (Docker Compose)

Проект полностью контейнеризирован в соответствии с техническим регламентом хакатона. Запуск осуществляется **одной командой**:

```bash
docker compose up --build
```

После завершения сборки и старта контейнеров решение доступно по адресам:

* **Веб-интерфейс ассистента:** [http://localhost:8080](http://localhost:8080)
* **Эндпоинт проверки здоровья (Healthcheck):** [http://localhost:8080/health](http://localhost:8080/health) (возвращает `200 OK` моментально)
* **Интерактивная спецификация API (Swagger):** [http://localhost:8080/docs](http://localhost:8080/docs)

> **Автономный режим (Zero-Config Offline Mode):** Приложение работает «из коробки» без обязательного указания API-ключей. При отсутствии внешних ключей агент использует локальный детерминированный NLU-движок и выполняет реальный поиск по валидированной базе из 2 666 отелей.
> 
> **Шифрование ключей для жюри (age):** Все секреты и API-ключи проекта зашифрованы публичным ключом организаторов в файле `secrets.env.age` в корне репозитория в соответствии с техническим регламентом хакатона. При проверке жюри расшифровывает файл своим приватным ключом.
> 
> **Подключение Google Gemini API (опционально для локального запуска):** Скопируйте `.env.example` в `.env` и укажите `GEMINI_API_KEY=ваш_ключ`.

## 2. Описание решения и проблематика

Классический поиск отелей требует от путешественника жестких входных данных (город, даты, количество гостей) и заставляет открывать десятки вкладок для сверки логистики, правил заселения и скрытых сборов.

**Ostrovok AI Agent** превращает одно свободное сообщение туриста в готовый, обоснованный сценарий поездки:
* Понимает неструктурированные запросы любой сложности текстом или голосом;
* Проверяет ограничения кодом, а не фантазией нейросети;
* Формирует прозрачный чек «под ключ» с учетом дороги, трансфера, сборов за питомцев и налогов;
* Объясняет выбор, подсвечивает компромиссы и доводит сценарий до имитации покупки.

## 3. Архитектура и инженерные стандарты

### 3.1. Запрет «AI-галлюцинаций» и строгий детерминизм
* **LLM используется исключительно для извлечения интентов и живого диалога:** Языковая модель извлекает слоты (направление, состав гостей, бюджет, даты, предпочтения).
* **Математика чека считается строго кодом (`backend/app/services/receipt_calc.py`):** Стоимость ночей, доплаты за животных, курортные сборы и логистика рассчитываются детерминированным алгоритмом. Модели запрещено вычислять итоговую сумму.
* **Smart Relaxation:** Если строгих совпадений 0, алгоритм мягко ослабляет второстепенные фильтры с открытым предупреждением пользователю («Бюджет превышен на 1 200 ₽»).

### 3.2. Двухэтапный гибридный поиск (Hybrid Retrieval)
1. **Семантический векторный этап (`vector_store.py`):** Векторная коллекция ChromaDB v2 с эмбеддингами `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`.
2. **Алгоритмический скалярный этап (`hotel_filters.py`):** Валидация по реальному каталогу 2 666 отелей по 19 туристическим направлениям с калиброванным Match Score (65%..98%).

### 3.3. Мультитерн и сохранение сессии (Multi-turn Slot Merging)
* Сервис `session_memory.py` реализует детерминированную машину состояний: при последовательных уточнениях («а теперь с бассейном», «покажи дешевле», «сдвинь на 2 дня») агент сохраняет накопленный контекст поездки на протяжении 2..10 шагов диалога, не сбрасывая город и гостей.

### 3.4. Отказоустойчивый каскад моделей (LLM Cascade)
* Цепочка fallback вызовов: `gemini-3.5-flash-lite` -> `gemini-3.5-flash` -> локальный детерминированный эвристический генератор.
* Жесткий таймаут на сетевые вызовы предотвращает зависание интерфейса в вечном лоадере.

### 3.5. Архитектура фронтенда: Feature-Sliced Design (FSD)
* Строгая модульная структура по методологии FSD на базе Next.js 14 App Router.
* Публичные интерфейсы модулей (`index.ts`), строгий линтинг границ (`eslint-plugin-boundaries`).
* Дизайн-система **Dark Swiss Minimalist**: тема на CSS-переменных токенах без хардкода HEX-цветов, соответствие стандартам доступности WCAG 2.1 AA.
* **Принцип Zero-Emoji:** полный запрет смайликов в коде и ответах ассистента; визуальные маркеры реализованы через SVG-иконки `lucide-react`.

## 4. Ключевые пользовательские сценарии и возможности

* **Голосовой ввод (Web Speech API):** Голосовое общение с визуализатором аудиосигнала в реальном времени.
* **Стартовые сценарии-онбординги (Quick Chips):** Быстрый выбор готовых направлений («В горы», «К морю», «На уикенд», «С собакой»).
* **Аспектный анализ отзывов гостей («Чё по отзывам?»):** Сервис `tag_reviews.py` извлекает подтвержденные плюсы, минусы и скрытые риски из реальных отзывов гостей каталога по категориям (шумоизоляция, чистота, завтраки, Wi-Fi).
* **Генерация коротких ссылок и шеринг поездки (`?trip=...`):** Сохранение полного состояния собранной поездки в URL для мгновенной передачи коллегам или жюри.
* **Мобильная адаптивность (Bottom Sheet):** Автоматическая адаптация сплит-экрана под смартфоны с интерактивной выпадающей шторкой выдачи.
* **Финальный чекаут и действия Post-booking:** Модальное окно подтверждения с номером заказа (`OST-DEMO-2026-XXXX`), интерактивными запросами (ранний заезд, добавление питомца, трансфер) и переходом на официальный чекаут Ostrovok.ru.
* **Защита от атак (Guardrails):** Детекция prompt-injection, попыток джейлбрейка и фильтрация нецелевого оффтопа с вежливым возвратом к планированию.

## 7. Локальная разработка (без Docker)

Если вы хотите запустить проект локально вне контейнеров:

### Требования
* **Node.js** 22 LTS и **Bun** 1.3+
* **Python** 3.11 и **uv** 0.12+

### Команды установки и запуска
```bash
# 1. Клонирование репозитория
git clone https://github.com/Neonchik4/ostrovok2026.git
cd ostrovok2026

# 2. Установка всех зависимостей фронтенда и бэкенда
bun run setup

# 3. Запуск в режиме горячей перезагрузки (Hot-reload)
bun run dev
```

Приложение откроется на:
* Фронтенд: [http://localhost:3000](http://localhost:3000)
* Бэкенд API: [http://localhost:8000](http://localhost:8000)
