## 2. Описание решения и проблематика

Классический поиск отелей требует от путешественника жестких входных данных (город, даты, количество гостей) и заставляет открывать десятки вкладок для сверки логистики, правил заселения и скрытых сборов.

**Ostrovok AI Agent** превращает одно свободное сообщение туриста в готовый, обоснованный сценарий поездки:
* Понимает неструктурированные запросы любой сложности текстом или голосом;
* Проверяет ограничения кодом, а не фантазией нейросети;
* Формирует прозрачный чек «под ключ» с учетом дороги, трансфера, сборов за питомцев и курортных налогов;
* Рассчитывает логистический компромисс стоимости жилья и трансфера;
* Предоставляет полную прозрачность затрат на вызовы LLM (окно Request Cost);
* Управляет фильтрами и каталогом в реальном времени через браузерного Ghost-агента.

## 3. Архитектура и инженерные стандарты

### 3.1. Запрет «AI-галлюцинаций» и строгий детерминизм бизнес-логики
* **LLM используется исключительно для извлечения интентов и живого диалога:** Языковая модель извлекает слоты (направление, состав гостей, бюджет, даты, предпочтения).
* **Математика чека считается строго кодом (`backend/app/services/receipt_calc.py`):** Стоимость ночей, доплаты за животных, курортные сборы и логистика рассчитываются детерминированным алгоритмом через Pydantic-модели. Модели запрещено вычислять итоговую сумму бронирования.
* **Smart Relaxation:** Если строгих совпадений 0, алгоритм мягко ослабляет второстепенные фильтры с открытым предупреждением пользователю («Бюджет превышен на 1 200 ₽»).

### 3.2. Двухэтапный гибридный поиск (Hybrid Retrieval)
1. **Семантический векторный этап (`vector_store.py`):** Векторная коллекция ChromaDB v2 с эмбеддингами `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`. Кодирует смысловой интент запроса («уютный тихий спа с панорамным видом»).
2. **Алгоритмический скалярный этап (`hotel_filters.py`):** Валидация по реальному каталогу 2 666 отелей по 19 туристическим направлениям с калиброванным Match Score (65%..98%). Учитывает фильтры звездности, цены, размещения с животными, дат и расстояния до хабов.

### 3.3. Мультитерн и слияние слотов (Multi-turn Slot Merging)
* Сервис `session_memory.py` реализует детерминированную машину состояний: при последовательных уточнениях («а теперь с бассейном», «покажи дешевле 10 000 руб», «сдвинь на 2 дня») агент сохраняет накопленный контекст поездки на протяжении 2..10 шагов диалога, не сбрасывая город, даты и гостей.
* Сброс слотов поиска происходит только при явной смене направления («хочу в Казань вместо Сочи»).

### 3.4. Отказоустойчивый каскад моделей (LLM Cascade)
* Цепочка fallback вызовов: `PRIMARY_MODEL` (`gemini-3.5-flash-lite`) -> `FALLBACK_MODELS` (`gemini-3.5-flash`, `gemini-flash-lite-latest`, `gemini-3.1-flash-lite`, `gemini-2.5-flash`) -> локальный детерминированный эвристический генератор.
* Жесткий таймаут на сетевые вызовы (не более 5-6 секунд) предотвращает зависание интерфейса в вечном лоадере. При исчерпании квот (HTTP 429) система немедленно возвращает информативный ответ.

### 3.5. Архитектура фронтенда: Feature-Sliced Design (FSD)
* Строгая модульная структура по методологии FSD на базе Next.js 14 App Router.
* Публичные интерфейсы модулей (`index.ts`), строгий линтинг границ (`eslint-plugin-boundaries`). Запрет кросс-импортов между сущностями и фичами.
* Дизайн-система **Dark Swiss Minimalist**: тема на CSS-переменных токенах в `globals.css` без хардкода HEX-цветов, соответствие стандартам доступности WCAG 2.1 AA.
* **Принцип Zero-Emoji:** полный запрет смайликов в коде, комментариях и ответах ассистента; визуальные маркеры реализованы через SVG-векторы библиотеки `lucide-react`.

## 4. Токеномика и прозрачность затрат (Request Cost & Observability)

В шапку сайта интегрировано окно аналитики **Request Cost** (кнопка рядом со Studio), обеспечивающее 100% прозрачность затрат на вызовы LLM в реальном времени:

* **Реальный учет токенов:** Извлечение точных счетчиков токенов из `usage_metadata` ответа Gemini (входные, кэшированные, выходные и reasoning/thinking токены).
* **Тарификация по официальному прайсу Google:** Стоимость рассчитывается в `backend/app/services/llm_usage.py` на основе актуального прайса Google Gemini API (Paid Tier Standard от 27.10.2026, файл `backend/app/data/llm_pricing.json`).
* **Бивалютный отчет ($ и ₽):** Пересчет стоимости запросов в рубли по курсу ЦБ РФ через переменную окружения `USD_RUB_RATE`. Если курс не задан, выводятся точные долларовые суммы без домыслов.
* **Сетевые метрики качества:** Замер времени до первого токена (TTFT, Time to First Token в миллисекундах) и скорости генерации (токенов в секунду).
* **Интеграция с Cloudflare AI Gateway:** Детекция кэшированных вызовов по заголовку `cf-aig-cache-status: HIT` с нулевой тарификацией кэшированных запросов.
* **История сессии вкладки:** Полный лог всех обращений к LLM в рамках текущей сессии с разбивкой по этапам (извлечение слотов, эмбеддинг поиска, генерация ответа) и кнопкой сброса.

## 5. Полноширинный каталог и браузерный Ghost-агент (/catalog)

Страница каталога отелей предоставляет интерактивный режим исследования выдачи с поддержкой DOM-автоматизации:

* **Полноширинная 3-колоночная компоновка:** Каталог развернут на всю ширину экрана: панель фильтров (266px), список карточек отелей и интерактивная карта.
* **Интерактивный Ghost-чат:** Компактный плавающий чат-интерфейс в правом нижнем углу каталога с поддержкой текстового и голосового ввода.
* **Бесшовная анимация призрака (Web Animations API):** Аватар маскота динамически перемещается между тумблером в шапке сайта, углом экрана и заголовком чата с сохранением 60 FPS без дерганий макета.
* **Управление страницей через DOM Steps:** Агент способен генерировать и выполнять точный план манипуляции элементами (установка ползунков цен, переключение фильтров питания, бассейна, питомцев, сортировка выдачи и плавный скролл к целевому отелю).
* **Три персоны поведения:**
  - `bro` — неформальный, энергичный тон для быстрого подбора;
  - `assistant` — деловой, сдержанный тон;
  - `luxury` — премиальный фокус на люкс-сегмент и спа-услуги.
* **Разворот карты:** Кнопка «Развернуть карту» раскрывает интерактивную карту на всю область страницы под шапкой с сохранением меток цен и карточек отелей.

## 6. Логистика, Transfer Trade-Off и умный расчет дороги

* **Алгоритм Transfer Trade-Off (`transfer_cost_calc.py`):**
  Агент оценивает компромисс между экономией на стоимости номера и скрытыми затратами на дорогу. Если более дешевый отель расположен далеко от транспортного хаба, система рассчитывает расстояние по формуле Haversine и стоимость такси, открыто предупреждая туриста:
  *«Экономия на стоимости проживания будет полностью нивелирована затратами на ежедневный трансфер»*.
* **Глубокие ссылки на транспорт (Deep Links):**
  Автоматическое формирование прямых ссылок на расписания поездов (РЖД) и авиабилетов (Яндекс.Расписания / Travelpayouts) с предзаполненными IATA-кодами станций/аэропортов и датами поездки.
* **Синхронизация заселения и выезда (Check-in / Check-out Timing):**
  Анализ времени прибытия транспорта: если рейс прибывает рано утром или поезд уходит поздно вечером, агент предупреждает туриста и подбирает отели с круглосуточной стойкой регистрации 24/7 либо опцией гарантированного позднего выезда.

## 7. Безопасность и защита от атак (Secure by Design Guardrails)

* **Двухуровневый шлюз безопасности (`guardrails.py`):**
  - **Injection Shield:** Детерминированная блокировка попыток промпт-инъекций, смены роли (Role Reversal), Jailbreak, инструкций DAN и попыток извлечения системного промпта. Запросы блокируются до вызова языковой модели.
  - **Offtopic Redirection:** Вежливая детекция запросов вне туристического контекста с автоматическим возвращением пользователя к планированию поездки без сброса накопленной сессии.
* **Защита от утечки секретов (Zero Secret Leakage):**
  Исходящий Server-Sent Events поток на каждом токене фильтруется санитайзером `sanitize_outgoing`, блокирующим передачу системных ключей, токенов провайдеров и внутренних конфигураций.
* **Санитизация и клампинг:**
  Все пользовательские строки очищаются от null-байтов (`sanitize_user_input`, лимит 1 000 символов на бэкенде, 500 в UI). Параметры клампятся в безопасные диапазоны (гости: 1..20, ночи: 1..90, цены > 0).

## 8. Сквозной Deep Linking и Post-Booking сценарий

* **Сериализация поездки в URL (`?trip=...`):**
  Полный контекст собранного маршрута (выбранный отель, параметры гостей, даты, фильтры) кодируется в компактный URL-параметр. Любой пользователь или член жюри, открывший ссылку, видит идентичную выдачу без необходимости авторизации.
* **Демо-чекаут и подтверждение бронирования:**
  Модальное окно с детерминированным номером брони (`OST-DEMO-2026-XXXX`), прозрачным чеком, интерактивными запросами (добавление питомца, ранний заезд, трансфер) и переходом на официальное бронирование на Ostrovok.ru.

1. **Сленг, топонимика и опечатки:** распознавание направлений в разговорной форме («сочик», «спб», «екб», «питер»).
2. **Конфликты бюджета:** разделение жестких рамок и психологической готовности («до 5000, но готов 7000»).

5. **Сложные календарные конструкции:** переходы между месяцами, праздники, относительные сдвиги дат.
6. **Мультитерн и уточнения:** добавление фильтров без потери базового контекста сессии.
7. **Граничные условия и клампинг:** нулевые и отрицательные числа, экстремальные значения ночей и гостей.

## 11. Локальная разработка (без Docker)

Для локального запуска вне Docker-контейнеров:

### Требования к окружению
* **Node.js** 22 LTS и **Bun** 1.3+
* **Python** 3.11 и **uv** 0.12+

### Команды установки и запуска
```bash
# 1. Клонирование репозитория
git clone https://github.com/Neonchik4/ostrovok2026.git
cd ostrovok2026

# 2. Установка всех зависимостей фронтенда и бэкенда
bun run setup

# 3. Запуск фронтенда и бэкенда в режиме горячей перезагрузки (Hot-reload)
bun run dev
```

Приложение откроется на:
* Веб-интерфейс: [http://localhost:3000](http://localhost:3000)
* Бэкенд API: [http://localhost:8000](http://localhost:8000)
