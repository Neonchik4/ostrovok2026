## 1. Контроль чистоты Git и синхронизация с `.gitignore`
* Перед каждой фиксацией изменений агент обязан вызывать `git status` и убеждаться в отсутствии нежелательных артефактов.
* Любые временные файлы, дампы отладки, локальные кэши (`.next`, `__pycache__`, `.pytest_cache`), динамические бинарники ChromaDB (`outputs/chroma_db_v2/**/header.bin`, `outputs/chroma_db_v2/**/link_lists.bin`) обязаны отсекаться файлом `.gitignore`.
* В коммиты не должны попадать бинарные артефакты сборки, временные логи и файлы локального окружения (`.env`, `*.local`).
* Lock-файлы `bun.lock`, `frontend/bun.lock`, `uv.lock` и версии `.bun-version`, `.python-version` сохраняются в Git. Не создавать параллельные npm lock-файлы или Python `requirements.txt`.
* После изменения зависимостей проверять frozen-установку Bun и `uv lock --check`; не запускать массовые обновления вместе с несвязанной задачей.

## 2. Стандарт коммитов (Conventional Commits)
* Сообщения коммитов пишутся в строгом формате Conventional Commits:
  * `feat(...)` — новая функциональность.
  * `fix(...)` — исправление дефекта.
  * `refactor(...)` — рефакторинг без изменения функциональности.
  * `test(...)` — добавление или изменение автотестов.
  * `chore(...)` — инфраструктурные настройки, зависимости, `.gitignore`.
* В коммит-сообщениях категорически запрещено использовать эмодзи.

---

## 3. Обязательный чек-лист перед коммитом
1. `bun run lint` — 0 ошибок и 0 предупреждений.
2. `bun run test` — все тесты Vitest и Pytest пройдены успешно (100% Pass Rate).
3. `git status` — рабочая директория содержит только целевые файлы задачи.
